# 账号预计总费用告警探针

Node.js 18+，不依赖第三方 npm 包。

## 配置

复制 `.env.example` 为 `.env`，填写：

- `WECOM_WEBHOOK_URL`
- `SUB2API_SERVERS`，以及每台服务器的地址、账号和密码

密码和企业微信 Webhook 只保存在本地 `.env`，不要提交到 Git。

可以同时监控多台服务器。`SUB2API_SERVERS` 用英文逗号分隔服务器标识，例如 `main,backup`。每台服务器使用自己的 `SUB2API_SERVER_<标识大写>_BASE_URL`、`EMAIL`、`PASSWORD` 和可选的 `NAME`。告警文本会带上对应服务器名称，同一条告警在不同服务器上分别计算静默时间。

每台服务器可以单独关闭监控。页面上的「监控」开关，或环境变量 `SUB2API_SERVER_<标识大写>_ENABLED=false`，都会保留这台服务器的地址、账号和分组，但巡检时跳过它。未填写时默认开启。全部关闭时不访问服务器，也不发送企业微信消息。

只监控一台时可以不填 `SUB2API_SERVERS`，改填 `SUB2API_BASE_URL`、`SUB2API_EMAIL`、`SUB2API_PASSWORD`。地址没有代码内置默认值，必须写在 `.env` 中。

每台服务器用 `SUB2API_SERVER_<标识大写>_MONITOR_ALL_ACCOUNTS` 单独控制“全账号预计总费用告警”，默认开启。它只统计这台服务器的全部可监控账号，不受该服务器的分组范围影响，也不会把多台服务器加在一起。未单独设置时沿用 `MONITOR_ALL_ACCOUNTS`。预计总费用阈值用 `SUB2API_SERVER_<标识大写>_ESTIMATED_COST_THRESHOLD`，单位 USD；未单独设置时沿用 `ESTIMATED_COST_THRESHOLD`。这台服务器的全账号合计和分组预计总费用都跟这个阈值比较。分组范围再用 `SUB2API_SERVER_<标识大写>_GROUP_SCOPE` 选择 `all` 或 `selected`；`selected` 时把分组名称写进对应的 `GROUPS`。分组告警按每个分组分别计算。

执行 `npm run ui` 后，也可以在本地页面里改 Webhook、服务器账号和分组。页面保存到 `data/monitor-config.json`，这份文件优先于 `.env`。页面只监听本机。

页面顶栏可以在配置和监控之间切换。监控只读取已启用服务器的当前用量，列出预计总费用低于阈值的分组和额度告急的账号，并显示预计总费用与 7d 已使用费用。两台服务器同时读取，谁先返回谁先显示。停留在监控页时每 30 秒自动再读一次；某台还在读取时不会重开这一台。监控读取不发送企业微信消息。

“采集完成”是探针完成本次读取的时间；“用量最早更新”是本次统计账号中，接口 `updated_at` 的最早有效时间，账号行也展示各自的用量更新时间。缺少时间的账号单独计数，全部缺少时显示“未知”，不会用采集时间冒充用量更新时间。批量接口仍使用 `force: false`，手动刷新和自动刷新都可能读取上游缓存，不承诺强制刷新上游用量。

页面默认打开监控概览，支持服务器筛选、仅看异常、搜索分组/账号、展开账号明细与单台刷新。汇总中的告急账号按服务器返回的去重数量统计，不重复累加多个分组里的同一账号。刷新失败时保留上次成功数据并标记“数据未更新”；从未成功读取的服务器不会显示为正常。

某台服务器巡检失败时，其他服务器仍会继续检查。失败原因会作为该服务器的一条告警。单次巡检因此以非 0 状态退出；定时巡检记录失败后继续下一轮。

## 运行

```powershell
node src/index.js --test
node src/index.js --once
npm run hourly
npm run ui
```

`--test` 只检查本地配置，不访问远程接口。`--once` 和 `npm start` 执行一次完整巡检。`npm run hourly` 会先立即检查一次，然后按 `CHECK_INTERVAL_MINUTES` 重复检查，默认 60 分钟。没有新的异常时不发送企业微信消息；定时进程遇到单次失败会保留下来，等下一轮继续检查。`npm run ui` 打开配置页面，默认地址是 `http://127.0.0.1:8787`。页面上的「告警一次」和「定时告警」由这个页面进程执行，开启后会先检查一轮，再按检查间隔重复。不要同时再运行 `npm run hourly`。

## 告警规则

- 某台服务器开启“全账号预计总费用告警”时，只把该服务器全部可监控账号的预计总费用相加，低于这台服务器的预计总费用阈值才告警。这项不受该服务器的分组范围影响，也不跨服务器合计。
- 监控范围内的每个分组，其账号预计总费用之和低于同一台服务器的预计总费用阈值。`all` 使用巡检时账号上出现的分组；`selected` 只计算勾选的分组。不再按 OpenAI 平台汇总。
- 单个账号 `5h` 或 `7d` 窗口剩余比例低于 `QUOTA_REMAIN_PERCENT`。
- 缺少 `5h` 窗口时，不发送 `5h` 告警。
- `utilization`、`used_percent` 和 `remaining_percent` 均按百分数读取，`1` 表示 `1%`，不会因数值小于等于 1 而乘以 100。`remaining_seconds` 仅表示重置倒计时，不能用来计算剩余额度；缺少有效百分数时不生成窗口额度告警。
- 相同告警在 `ALERT_COOLDOWN_MINUTES` 内只发送一次。

预计总费用与管理台一致：优先使用接口直接返回的预计总费用字段；否则在 7 日窗口的 `utilization` 和 `window_stats.cost` 都是大于 0 的有限数字时，按 `cost * 100 / utilization` 估算。不会用预付余额、钱包余额或配额余额替代。成功拿到用量但没有费用字段时保持未知，显示为 `--`，不参与预计总费用告警；这类账号仍继续检查单账号窗口额度。

预计总费用不是实际剩余余额，也没有扣除已使用费用。低使用率或百分数粒度较粗时，估算会明显波动；费用估算告警和窗口剩余比例告警是两个独立指标，不能用估算金额反推账号是否耗尽。

用量查询也与管理台一致：Anthropic OAuth / Setup Token 使用 `source=passive`，其余会展示用量的账号走主动查询，并优先使用批量接口。管理台不查询用量的账号不参与合计，也不会让巡检失败。某台服务器的用量获取失败时，不使用残缺数据计算该服务器的费用，并单独报告这台服务器巡检失败。

## 测试

```powershell
node --test
```

`npm run ui:preview` 在 `http://127.0.0.1:8790` 启动独立界面预览（可用 `PREVIEW_PORT` 更改端口）。预览只使用示例数据，不读取 `.env`、不连接实际服务器，且拒绝保存配置和发送告警。

`npm run test:ui` 运行浏览器验证，需要开发环境提供 Playwright；可用 `PLAYWRIGHT_MODULE` 指定其模块路径、`BROWSER_EXECUTABLE` 指定浏览器路径、`UI_SCREENSHOT_DIR` 指定截图目录。检查包含桌面和手机布局、筛选、搜索、折叠、无数据与失败重试，并断言不会访问外部服务或发送告警。应用运行本身无需新增 npm 依赖。图标来自本地打包的 Lucide，许可证见 `web/vendor/lucide-LICENSE.txt`。
